items

Press the button. The page then asks for the same rows three times. Nothing is sent before that.

Address

GET /rest/v1/items?select=name,sku,quantity

That is the Data API for the public.items table. select asks for those three columns. The address is the same in every column.

Headers

apikey is the publishable key. It names this project. It is the same in all three columns.

Authorization says who is asking. That header is the only difference.

Visitor

The visitor sends the publishable key as Authorization. There is no signed-in person, so the API uses the anon login. Row level security is on, and no policy names anon. The request is accepted and the list is empty. HTTP 200 with [] means the call worked, and no rows were returned.

Ada and Bea

Each of them is signed in first. The page posts the email and password to /auth/v1/token?grant_type=password, still with the publishable key as apikey. The response carries an access token. That token is sent as Authorization on the items request. The API uses the authenticated login and sets auth.uid() to the account id inside the token.

Why the lists differ

The policies keep a row when owner_id equals auth.uid(). Ada's id owns the Notebook and the Pen. Bea's id owns the Stapler. The two tokens carry different ids, so the two lists are different. Neither person receives the other's rows.
